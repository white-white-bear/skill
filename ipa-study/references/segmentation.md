# 文本整理

把词级时间戳变成断好句、分好段的正文。这一步决定后面所有对齐的质量。

## 断句：停顿是硬证据，标点是编辑判断

- **句界靠停顿。** 词间间隔 ≥ `segment.sentence_gap_sec`（默认 0.60 秒）且
  当前句已有 `min_sentence_words`（默认 4）个词，就断开。
  0.60 不是拍脑袋：基准素材词间 gap 的 p99 是 0.58 秒、p99.5 是 0.72 秒，
  取 0.60 恰好切在"正常换气"和"真的停顿"之间。
- **Whisper 的 segment 句末标点是免费证据。** 声学模型判断这里说完了，
  在停顿不到 0.6 秒的地方也值得采信。
- **标点由 agent 补。** `segment` 生成的草稿只做机械处理：句首大写、句尾补句号。
  真正的逗号、分号、引号由人/agent 在 `chNN_final.txt` 上改。

为什么把标点从代码里拿出来：加标点需要读懂语义，而**改标点和改词只差一个
手滑**。让人在纯文本上改，改完的 token 序列就是最终序列；如果让模型输出结构化
标点指令，就有它在别处顺手改词的风险，那种错误会让音标和音频错位，
而且**看不出来**——这是本产品最隐蔽的失效方式。

## 粘连词

`whilein`、`MontaLoma` 这类是字幕/转写的常见产物。

拆分条件（全部满足才拆）：

1. 不在项目词典、cmudict、功能词表里，长度 ≥6，纯字母；
2. 两半都在词典里；
3. 有一半是功能词（加分），或两半都在这段 ASR 的上下文里出现过（加分）；
4. **最高分明显领先第二候选**（差 ≥0.5）且绝对分 ≥1.0。

第 4 条是关键：拆错的粘连词比不拆难查得多。拆不动的写进
`data/segment/review.json`，交给人看。

## 什么时候可以跳过 DP 对齐

对齐前先算两个数：`ratio = n_text / n_asr`，以及**带宽 DP 的实际匹配率**。

> 不要用"逐位比对"算相似度。正文和转写只要中间错开一个词，后面全对不上，
> 逐位得分会掉到 0.1，把明明只是错位的两份文本判成完全不同。

| 匹配率 | 模式 | 复杂度 |
|---|---|---|
| 长度相等且逐位 ≥0.98 | `identity` 直配 | O(n) |
| ≥0.60 | `banded` 带宽 DP（B=24） | O(n·B) |
| <0.60 | `windowed_nw` 先找锚点再开窗 | O(n·B) |

带宽 DP 的终点不可达时会自动放宽带宽（×2、×4、最后不限），所以带太窄不会
报错，只会变慢。

## 锚点：最长连续命中段

`windowed_nw` 模式下，用本章前 40 个词在全片里找起点，取**最长连续命中段**
的开头。

- 只看第一个命中会被 "the" 这类孤立词骗走；
- 只看最后一个命中会被吸到文件末尾——探针结束后剩下的参考词无论落在哪都要
  记成空位，末尾几组对位几乎打平。

连续命中不足 4 个视为没找到，退回用上一章的锚点。

## 未匹配的词必须插值，不能塞零头

VAD 偶尔会整段吞掉旁白。对这些词：

- 按**音素数**（不是字符数）在前后两个已匹配词的空档里均摊；
- 标记 `asr = null`，**不参与重读判定**——它的时间是插出来的，测出来的音高
  不能当证据；
- 在 `align/report.json` 里记下每章未匹配率。

之前踩过的坑：每词硬塞 0.08 秒，测出来的时长和音高全是假的，但成品上看不出来。

## 门槛

| 指标 | 合理区间 | 出界说明 |
|---|---|---|
| 平均句长 | 8–25 词 | 断句阈值不合适 |
| 单句 | ≤45 词 | 该断没断，进 review |
| 每段 | 20–120 词 | 段落阈值不合适 |
| 未匹配率 | ≤2% | 文案和音频可能不是同一个素材 |
