# 素材形态

同一条流水线遇到的素材差别可以很大。这一页记的是"先判断再动手"，以及
判断错时会连锁引发哪些错误。

## 先跑 `ipa profile`

转写一结束就跑，别等分章的时候才发现方向错了。

```bash
ipa profile job.json           # 只看结论
ipa profile job.json --apply   # 把建议写回 job.json
```

它统计五件事：

| 指标 | 从哪来 | 说明什么 |
|---|---|---|
| 词速率 | 词数 / 时长 | 正常叙述 140–160 词/分 |
| 有声占比 | 词时长之和 / 全程 | 低说明有大量停顿或留白 |
| 停顿中位数 / p90 | 词间空档 | 双峰说明有"句间留白"这种结构 |
| 条目数 | 按 ≥3 秒停顿切 | 和总句数差很多，说明素材有段落节奏 |
| 相邻重复率 | 条目内最长重复段 | 高 = 每句念了不止一遍 |

## 四种形态

### `narrative` 叙述型

连续讲述，句子长。纪录片、演讲、有声书都属于这类。

- 分章靠内容和停顿结合
- 保留全书地图（地图有故事线可画）
- 每章三个回忆问题成立
- 正常开 gapfill

### `shadowing` 影子跟读

每句念两遍（或者更多），中间留一两秒，是给你张嘴的。

**这是最容易做错的一类。** 实测一份 68 分钟的跟读材料：304 条里 275 条含重复，
语速 56 词/分，有声占比 52%。

如果不知道这一点，会连着做错四件事：

1. 按目录/时长分章 → 章节和内容对不上
2. 把练习留白当 VAD 丢词 → 去补转，白跑十几分钟
3. 按时长判成"分章全书" → 得到一本每章 200 词的书
4. 每句一个段落 → 每句后面跟一个空白小结框，一页放不下四句话

正确做法：

- `asr.dedupe.enabled = true`，只留第一遍
- `asr.gapfill.enabled = false`（留白是真静音——先测，见下）
- 形态按**词数**选，不按时长
- `segment.paragraph_gap_sec` 调大，改按句数分组（5 句一段）
- 关掉全书地图（没有故事线）

### `drill` 练习型

大段留白，但没有重复。跟读材料去掉重复后的样子，或者带听写间隔的教材。

处理接近 shadowing，只是不用开 dedupe。

### `mixed` 介于两者之间

语速慢、句子短，但没有明显留白。谨慎处理，别自动关地图。

## 判断"静音"还是"VAD 丢词"

这两种情况看起来一样（词表里出现长空档），处理方式相反：前者该关 gapfill，
后者必须开。

**测一下就有答案**：取几个长空档，用 Praat 的强度轨看平均响度。

```
有词的区间      约 60 dB
真静音          −280 dB 以下（数字静音）
音乐 / 环境声   10–40 dB
```

如果空档是 −280 dB 那一档，就是真的什么都没说，补转纯属浪费。

## 结构可能就写在音频里

跟读材料里主持人经常自己报幕："欢迎来到第一部分……接下来是第二部分"。
这比任何算法都可靠——直接在转写里搜这些句子，把它们的时间戳当章节边界。

```bash
# 在 words.jsonl 里找关键短语
grep -o "part two" data/words.jsonl
```

或者读一遍转写，找 "welcome to"、"now let's"、"that's the end of" 这类转场句。

## 词数比时长可靠

时长会骗人：68 分钟里可能只有 2000 多个词。`form_for()` 优先用词数：

| 词数 | 形态 |
|---|---|
| < 1500 | 单篇 |
| 1500–6000 | 分节（3–8 节） |
| > 6000 | 分章全书（8–14 章） |
